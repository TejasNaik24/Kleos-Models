# Training on Kaggle

Kaggle's free tier offers two Tesla T4s in one notebook session, which Colab's
free tier does not. Logos v0.0.2 needed both: its reasoning traces lengthened the
longest training example to 736 tokens, and at that length one T4 does not hold
Logos' settings (estimated 14.46 GB against a 14.41 GB budget). On 2 × T4 it
trained in one session of 4.4 hours and was evaluated in another of 5.2 hours.

The exact commands, hashes and comparison for that run are in
[runbooks/logos-v002-kaggle.md](runbooks/logos-v002-kaggle.md).

## How the notebooks differ from Colab's

A Kaggle notebook committed with **Save Version → Save & Run All (Commit)** runs
unattended on Kaggle's side, with no browser attached, and keeps only what it
writes to its working directory as the version's output. The notebooks in
the `notebooks/kaggle` folder are written for that:

- **Every command stops the run on failure.** A failing `!command` would not stop
  a notebook, so commands go through a `run()` helper that streams the output and
  raises on a non-zero exit.
- **Nothing private reaches the saved output.** Code, data and model weights stay
  in `/tmp`, which Kaggle never saves; only `outputs/` goes to the working
  directory.
- **A session ends cleanly before Kaggle's limit** (below), so the output needed
  to resume is always saved.

The notebooks are generated by `scripts/build_kaggle_notebooks.py`, and
`tests/test_kaggle_notebooks.py` checks them. CI regenerates them and fails if
the committed files differ.

## Account prerequisites

- **Phone verification.** Kaggle requires it for GPUs and for internet access
  from a notebook.
- **GPU quota.** About 30 GPU hours a week on the free tier as of 2026-10. The
  Logos v0.0.2 training and evaluation used about 10.5.
- **The code pushed.** The notebook clones the repository at a commit, so that
  commit must be on the remote. Note its full 40-character sha.

## Upload the dataset as a private Kaggle dataset

**New Dataset → upload the files → Private.** For a KLEOS release, upload its six
files: `train.jsonl`, `validation.jsonl`, `test.jsonl`, `manifest.json`,
`provenance.json` and `RELEASE.lock`.

The notebook finds the release among its inputs by `RELEASE.lock`, refuses unless
exactly one release is attached (identical copies count once), copies it to
`/tmp` at the path the run's config hash was computed with, and checks the
sha256 of `test.jsonl` against the sealed one. Attached inputs are read-only, so
it copies them to a writable location first.

## Check once that a failed version's output can be attached

Resuming depends on attaching a stopped or failed version's output as an input to
the next version. Check that before relying on it; it takes about two minutes and
no GPU:

1. Import `output_probe.ipynb` from `notebooks/kaggle` and **Save & Run All**. It writes
   `probe/marker.txt` and then fails on purpose.
2. In any notebook, **Add Input** → that notebook's output. If `probe/marker.txt`
   is there, failed versions keep their output and the resume steps below work.

If the marker is missing, a run that stops must start over.

## Run a notebook

1. **File → Import Notebook** and choose the notebook from `notebooks/kaggle`.
2. **Settings:**
   - **Accelerator → GPU T4 x2.** The hardware cell refuses anything else.
   - **Internet on**, to clone the code and download the base model.
   - **Environment → Pin to original environment**, so a resumed version runs the
     same libraries. A resumed evaluation refuses to continue if library versions
     changed, because they are part of its identity.
3. **Add Input** → the private dataset (and, for an evaluation, the finished
   training output).
4. In the first code cell, set `COMMIT` to the full sha. A branch name or the
   placeholder is refused.
5. **Save Version → Save & Run All (Commit).**

What the training notebook does, in order, stopping at the first failure:

1. checks for exactly two T4s and 30 GB free in `/tmp` for the model weights;
2. clones the repository at `COMMIT`;
3. runs `scripts/colab_setup.py`, which keeps Kaggle's torch, then installs the
   pinned library versions with `--no-deps`
   (`transformers==5.16.1 peft==0.20.0 accelerate==1.14.0 bitsandbytes==0.50.2 tokenizers==0.23.2`);
4. sets `HF_HOME` under `/tmp` and refuses to continue if any `KLEOS_*` variable
   is set, since those change the config hash;
5. copies and checks the dataset;
6. restores checkpoints from an attached previous version, if any;
7. refuses to train unless `config_hash` equals the pre-registered one;
8. plans against the live GPUs;
9. runs a ten-step smoke run and the memory gate (`scripts/check_smoke_gate.py`),
   skipped when resuming a run that already passed it;
10. trains with `--resume-from-checkpoint auto`.

## The 11¼-hour guard

Kaggle ends a GPU session at 12 hours, and a session killed at the limit may not
save its output. The notebooks record the session start and stop any long command
at 11¼ hours (`SESSION_HOURS = 11.25` in the builder). After that, every later
command is skipped, the version ends normally and its output is saved, and the
last cell prints **NOT FINISHED** with the instruction to resume.

## Resume a run that stopped

Whether it hit the guard, an error or the quota:

1. **Add Input** → this notebook's previous version **output**.
2. **Save & Run All** again.

For training, the checkpoints are copied back and training resumes from the
latest complete one. A checkpoint missing `optimizer.pt` or `scheduler.pt` is set
aside first, with a printed `L-F5` line, because transformers would otherwise
resume it with a fresh optimizer and a restarted schedule without warning
(finding L-F5, recorded in [experiments/logos-findings.md](experiments/logos-findings.md)).
The notebook always resumes with `auto` and never starts fresh over existing
checkpoints (finding L-F4).

For evaluation, the partial results file is copied back, and finished generations
are replayed, not regenerated ([evaluation.md](evaluation.md#resuming-an-evaluation)).

Attach at most one previous version: with two, the notebook stops rather than
choose.

## Where things live during a session

| Location | Holds | Saved with the version |
| --- | --- | --- |
| `/tmp` | the cloned code, the dataset copy, the model cache (`HF_HOME`), the smoke run | no |
| The working directory (20 GB) | `outputs/<experiment-id>/`: adapter, manifest, metrics, checkpoints, results | yes |
| Attached inputs | the dataset, earlier versions' outputs | read-only |

Neither notebook publishes anything. To use a result elsewhere, download it from
the version's output; the H9 comparison, for example, ran on a CPU outside Kaggle
from the downloaded `arm2_finetuned.json`.

## What the Logos v0.0.2 run recorded

- Both notebooks ran on Kaggle's latest container image; "Pin to original
  environment" was not set. Neither run resumed, so it had no effect (deviation
  D12 in [experiments.md](experiments.md#deviations-log)).
- The first training version stopped in its first cell because `COMMIT` still held
  its placeholder; no code beyond the guard ran (deviation D13).
- `evaluate.py` prints no per-answer progress, so a five-hour evaluation shows
  nothing until it ends (finding L-F8).

The full record is indexed in [experiments/README.md](experiments/README.md).

## Adapting the notebooks to another run

The run's constants sit at the top of `scripts/build_kaggle_notebooks.py`:
experiment id, dataset and output paths, config hash, the sha256 of `test.jsonl`
and of the benchmark, the library pins and the session limit. The dataset and
output paths are inputs to the config hash, so a new run records new ones. Edit
the builder, regenerate, and commit the regenerated notebooks with the change:

```bash
python scripts/build_kaggle_notebooks.py
python -m pytest tests/test_kaggle_notebooks.py
```
